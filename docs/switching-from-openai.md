# Switching from Spring AI's OpenAI starter

Use this page when an application moves from `spring-ai-starter-model-openai` to this starter. Code that uses `ChatClient`, `Prompt`, `ChatResponse.getMetadata().getUsage()` and `Generation.getMetadata().getFinishReason()` keeps working. Some behavior differs, and this page lists each difference.

The comparison is with the OpenAI module of Spring AI 2.0.2, the version this library builds against.

## Change the dependency, selector and prefix

1. Replace the `spring-ai-starter-model-openai` dependency with `openrouter-spring-ai-starter`. See [Getting started](getting-started.md#install-and-make-a-first-call).
2. Set `spring.ai.model.chat=openrouter`. Do the same for each other [model selector](getting-started.md#spring-ai-model-interfaces) that the application uses.
3. Rename the property prefix from `spring.ai.openai` to `spring.ai.openrouter`, and check each property against the pages linked below. The chat properties are flat in both starters, for example `spring.ai.openai.chat.model` and `spring.ai.openrouter.chat.model`.
4. Use OpenRouter model names, such as `openai/gpt-5.4-mini`, and an OpenRouter API key.

## What behaves differently

| Area                                             | Spring AI OpenAI starter 2.0.2                                                                                                | This starter                                                                                                                                                                                                                                                               |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Retries                                          | The OpenAI SDK retries. `spring.ai.openai.max-retries` sets the count, and the default is 3. `spring.ai.retry.*` is not read. | Spring AI's `RetryTemplate`, which Boot builds from `spring.ai.retry.*`. Streams retry only an HTTP 429 that arrives before the first event. See [Errors and retries](errors-and-retries.md).                                                                              |
| Timeout                                          | `spring.ai.openai.timeout` or `spring.ai.openai.chat.timeout`. When neither is set, the OpenAI SDK default applies.           | `spring.ai.openrouter.connection.timeout`, with a 2-minute default. See [HTTP, timeouts and limits](http-and-limits.md).                                                                                                                                                   |
| Exceptions                                       | OpenAI SDK exceptions.                                                                                                        | `OpenRouterTransientApiException` and `OpenRouterNonTransientApiException`, which extend Spring AI's `TransientAiException` and `NonTransientAiException`. Every library failure implements `OpenRouterFailure`. See [What to catch](errors-and-retries.md#what-to-catch). |
| Reasoning text                                   | Message metadata `reasoningContent`, which is replayed on the next request.                                                   | Message metadata `openrouter.reasoning`. Replay uses `openrouter.reasoning_details`, so a stored `reasoningContent` is not replayed. See [Reasoning and prompt caching](reasoning-and-caching.md).                                                                         |
| Refusal                                          | Message metadata `refusal`.                                                                                                   | Message metadata `openrouter.refusal`.                                                                                                                                                                                                                                     |
| `id`, `role`, `finishReason`, `index`            | Message metadata.                                                                                                             | Not in message metadata. Use `ChatResponse.getMetadata().getId()`, `getMessageType()` and `Generation.getMetadata().getFinishReason()`. Chat streaming sets `openrouter.choice_index` in generation metadata.                                                              |
| `annotations`                                    | Message metadata.                                                                                                             | Inside `openrouter.message.extensions`. See [Optional request and response extensions](extensions.md).                                                                                                                                                                     |
| `created`                                        | Response metadata `created`.                                                                                                  | Response metadata `openrouter.created`.                                                                                                                                                                                                                                    |
| Finish reasons                                   | `STOP`, `LENGTH`, `TOOL_CALLS`, `CONTENT_FILTER` and `FUNCTION_CALL`.                                                         | The same values for stop, length, tool calls and content filter. The legacy `function_call` becomes `TOOL_CALLS`. A value that the library does not know passes through unchanged.                                                                                         |
| Rate limit                                       | Blocking calls read the `x-ratelimit-*` headers into `getRateLimit()`.                                                        | An empty rate limit. OpenRouter's [limits page](https://openrouter.ai/docs/api_reference/limits) says that successful inference responses carry no `X-RateLimit-*` headers.                                                                                                |
| Empty `choices` in a blocking call               | A warning and an empty `ChatResponse`.                                                                                        | `OpenRouterProtocolException`.                                                                                                                                                                                                                                             |
| Custom headers and per-model connection settings | `spring.ai.openai.custom-headers`, and an `api-key`, `base-url` and `timeout` for each model.                                 | One connection for all models. To add headers, customize the HTTP client as [HTTP, timeouts and limits](http-and-limits.md) describes.                                                                                                                                     |
| Moderation                                       | `OpenAiModerationModel`.                                                                                                      | Not available. OpenRouter has no moderation endpoint.                                                                                                                                                                                                                      |

`OpenRouterMetadata` has a constant and a typed reader for each `openrouter.*` key, so application code does not need the string names. See [Observability](observability.md).

## Stored conversations

A conversation history that was stored with the OpenAI metadata keys needs conversion before this starter can continue it. Renaming the keys is not enough for reasoning: this library replays the opaque `openrouter.reasoning_details` value that OpenRouter returned, and OpenAI's `reasoningContent` text does not contain it. A converted history therefore continues without the earlier reasoning state.

Tool calls and tool responses use Spring AI's own message types in both starters and need no conversion.
